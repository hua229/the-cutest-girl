# v2.6 顶部栏与图片间距优化方案（规范说明，不含代码）

> 基线版本：v2.5.7（versionCode 22）
> 范围：仅顶部栏收缩交互、设置按钮归属、上传页图片与容器间距三项，不涉及数据层与同步层。

---

## 一、顶部栏滚动收缩为左上角小胶囊

### 1.1 现状与问题

现在滚动时的「收缩」只做了两件事，视觉上并不是胶囊：

| 项目 | 当前实现 | 结果 |
|---|---|---|
| 副标题 | `AnimatedVisibility(!collapsed)` 淡出 + `shrinkVertically` | 高度减少 20dp |
| 日期条 / 月条 | `AnimatedVisibility(!scrolled)` 整块收起 | 高度减少 44～52dp |
| 玻璃面板宽度 | `Modifier.weight(1f)`，始终撑满「屏宽 − 16dp×2 − 44dp 齿轮 − 10dp 间距」 | **仍是一条几乎全宽的横条** |

实测展开高度（含面板上下各 6dp 外边距）：

- 穿搭（标题 + 副标题 + 月份行 + 日条）≈ **152dp**
- 饮食（标题 + 副标题 + 日期行）≈ **128dp**
- 事件（标题 + 副标题）≈ **96dp**

收缩后三页都降到 ≈ **56dp**，但横向依旧铺满，所以观感是「一条白横条」而不是「一颗胶囊」。

### 1.2 目标形态

收缩态 = 左上角一颗玻璃胶囊：

| 参数 | 规范值 | 说明 |
|---|---|---|
| 高度 | **40dp** | 比展开态的标题行（34dp）高 6dp，容纳 26sp 标题不裁切 |
| 圆角 | **20dp** | 胶囊语义 = 高度/2 |
| 水平内边距 | **14dp**（左右） | 与展开态 `PageHeader` 的 `start 14dp` 对齐，收缩时标题文字不会横向跳位 |
| 内容 | emoji + 页面名 | 副标题、日期条全部不进入 |
| 与屏幕左间距 | **16dp** | 与展开态 `GlassTopBarWithSettings` 的水平 padding 一致 |
| 与状态栏间距 | **6dp** | 与展开态 `vertical 6dp` 一致 |
| 玻璃材质 | 沿用 `glassMaterial`（`blurRadius 22dp`、`noise 0.06f`、`tintScale 0.72f`） | 不重新定义品牌视觉，与底栏同一套 |

### 1.3 交互规则

1. **触发阈值**：沿用现有 `derivedStateOf { firstVisibleItemIndex > 0 || firstVisibleItemScrollOffset > 16 }`，即列表首项滚出 16dp 后进入收缩态。不改阈值，避免与现有 `collapsed` 逻辑打架。
2. **收缩动画**：
   - 宽度：`FastOutSlowInEasing`，**300ms**
   - 高度：`FastOutSlowInEasing`，**240ms**
   - 展开（回到顶部）反向播放，时长不变，不做弹性回弹（避免长列表来回滚动时抖动）
3. **收缩态可点**：点胶囊 → 列表 `animateScrollToItem(0)` 回到顶部，随后自动展开。**不做「点一下手动展开」**——展开态由滚动位置唯一决定，手动展开会和滚动状态冲突。
4. **齿轮归属**：收缩态胶囊右侧**保留** 44dp 齿轮（仅穿搭页，见第二节），与胶囊间距 10dp（沿用现有值）。

### 1.4 实现约束（供开发参考，非代码）

- `Modifier.weight(1f)` **不能做宽度动画**。需要把外层 `Row` 改成：`胶囊(width = 动画值)` + `Spacer(weight(1f))`，让剩余空间由 Spacer 吃掉，胶囊宽度才可动画。
- 面板内部内容在收缩态要 `clip` 到胶囊圆角内，否则副标题淡出过程中会溢出圆角。
- 收缩态撤销 `PageHeader` 的 `emphasized` 阴影（elevation 8dp → 4dp），胶囊比面板轻。

### 1.5 验收标准

1. 列表滚到第 2 项时，左上角只剩一颗 ≤ 40dp 高的胶囊，右边缘不超过标题文字右端 + 24dp。
2. 滚回顶部，胶囊在 300ms 内恢复全宽，副标题、日期条依次淡入，无跳变、无重叠。
3. 点击胶囊后 600ms 内回到列表顶部，期间无白屏或列表闪动。
4. 穿搭 / 饮食 / 事件三页行为与时长完全一致。

## 二、设置按钮仅保留在穿搭模块

### 2.1 现状与问题

- `GlassTopBarWithSettings` 被三个页面共用，因此**饮食页、事件页右上角也各有一个 44dp 齿轮**。
- 三个页面都向 `AppRoot` 传了 `onOpenSettings = { navController.navigate("settings") }`，设置页本身是全局路由。
- 后果：同一个功能在三个页面各留一个入口，顶部栏控件不统一；事件页顶部栏只有 96dp 高，右上的齿轮在视觉上反而成了主角。

### 2.2 目标形态

| 模块 | 顶部栏组件 | 齿轮 |
|---|---|---|
| 穿搭 | `GlassTopBarWithSettings`（面板 + 齿轮） | **保留** |
| 饮食 | `GlassTopPanel` 单独使用，宽度占满（左右各 16dp） | **移除** |
| 事件 | 同上 | **移除** |

### 2.3 规范统一项

三页顶部栏必须完全一致的部分（避免"割裂"）：

- 左右外边距 **16dp**、上下 **6dp**
- 面板圆角 **26dp**、elevation **8dp**
- 玻璃材质参数与底栏同源
- 标题 emoji 尺寸 **22sp**、emoji 与文字间距 **8dp**
- 标题字号 `headlineMedium`（26sp / 34sp）

只有「右侧是否有 44dp 齿轮 + 10dp 间距」这一项不同。

### 2.4 影响面与注意事项

- **设置入口路径变化**：饮食页、事件页要改 WebDAV 账号 / 昵称 / 看同步状态，需要先切回穿搭页进齿轮。这是本条的必然后果，需产品侧确认接受。
- 通知点击进入 App 后落在穿搭页，仍能进设置，**不受影响**。
- `AppRoot` 中 `meal`、`event` 两个 `composable` 不再需要 `onOpenSettings` 实参；`MealScreen`、`EventScreen` 的形参同步移除（保留会导致调用处编译报错）。
- 事件页顶部栏由「面板 + 齿轮」变为「面板全宽」后，`PageHeader` 右内边距需从 `6dp` 放大到 **12dp**，否则标题右端贴边。

### 2.5 验收标准

1. 饮食页、事件页顶部栏右侧无齿轮，面板右边缘距屏幕右侧 16dp。
2. 穿搭页齿轮仍在原位，可正常进入设置页。
3. 三页标题的左起点 x 坐标一致（误差 ≤ 1dp）。
4. 三页顶部栏的面板圆角、阴影、玻璃透明度观感一致（截图对比无差异）。

## 三、上传图片无文字备注时的间距优化

### 3.1 现状与问题

`PhotoNoteCard` 自上而下是：照片区 → 照片操作行 → 1dp 发丝线 → 备注输入框。问题有三处：

**(1) 备注区最小高度是常驻的**
`TextField` 固定 `minLines = 3`：正文 15sp / 行高 23sp × 3 = 69dp，加上 TextField 自带上下内边距各 16dp，**共 101dp**。
即使一个字都没写，这 101dp 也照样占着。

**(2) 无照片 + 无备注时整卡过高**
画像：照片区空态（两枚胶囊 + 16dp 内边距）≈ 70dp + 分割线 1dp + 备注 101dp ≈ **172dp**，
其中 **101dp 是纯空白**，卡片看起来"虚胖"。

**(3) 照片边距与文字边距是两套**
- 单图：**贴边铺满**，无内边距（`clip` 只切上两角）
- 多图：内边距 **8dp**，图间距 8dp
- 备注文字：左起点 **16dp**
- 分割线：左右 **16dp**

同一张卡片里出现 0dp / 8dp / 16dp 三种留白，视觉上"图片顶到边、文字缩进来"，这是最明显的割裂。

### 3.2 目标形态

#### (1) 备注区随内容收缩

| 状态 | 表现 |
|---|---|
| 空备注（未聚焦） | 收成一行「＋ 写点备注（可选）」，`labelMedium`，`onSurfaceVariant 80%`，行高 17dp + 上下内边距 12dp = **41dp** |
| 空备注（点击后） | 展开为标准输入区，`minLines = 3`，光标在首行 |
| 有备注 | 直接按内容高度显示，不限行数 |
| 失焦且内容为空 | 收回成一行入口 |

高度变化统一加 `animateContentSize()`，时长 180ms，避免展开/收回时卡片"跳"一下。

#### (2) 空备注时不画分割线

没有备注内容时，照片区与备注入口之间不需要 1dp 分隔线；只在**有备注文字**时显示。

#### (3) 间距规范统一（12dp 基线）

| 位置 | 规范值 |
|---|---|
| 卡片内边距（四边） | **12dp** |
| 单图与卡片边缘 | **12dp**（不再贴边），图片圆角 **12dp** |
| 多图之间 | **8dp**（保持现状） |
| 多图与卡片边缘 | **12dp** |
| 照片区 → 操作行 | **12dp** |
| 操作行 → 分割线 | **12dp** |
| 分割线 → 备注文字 | **12dp** |
| 卡片圆角 | **20dp**（不变） |
| 卡片 elevation | 6dp（不变） |

单图不再贴边后，卡片顶部会出现 12dp 白边，与底部备注区对称——这正是诉求里要的"图片与容器间距"。

#### (4) 空态（还没选照片）

「从相册选择 / 拍一张」两枚胶囊：胶囊高 38dp，卡片内边距 12dp → 卡片总高 **62dp**。
无分割线、无备注入口（此时备注没有意义，先让用户选图）。

### 3.3 验收标准

1. 未选照片、未写备注：卡片总高 ≤ **64dp**，无多余空白。
2. 选 1 张照片、不写备注：照片下沿到卡片底边 = **12dp**，备注入口单行显示，卡片不出现 3 行空白。
3. 写备注后卡片自动长高，长高过程平滑（无跳变），备注文字左起点与照片左边缘对齐同一条 **12dp** 基线。
4. 多图（2/4/9 张）状态下，图与图 8dp、图与卡片 12dp，无贴边。
5. 上传页、穿搭编辑页、事件编辑页三处共用同一组件，改后三页表现一致。

## 四、影响范围汇总

| 文件 | 改动性质 |
|---|---|
| `ui/components/Common.kt` | `PageHeader` 收缩态胶囊化；`PhotoNoteCard` 备注区折叠 + 间距规范化 |
| `ui/components/Glass.kt` | `GlassTopBarWithSettings` 支持「无齿轮」形态；胶囊形态的圆角/高度参数 |
| `ui/outfit/OutfitScreen.kt` | 继续用带齿轮版本 |
| `ui/meal/MealScreen.kt` | 去掉齿轮；顶部栏改面板全宽 |
| `ui/event/EventScreen.kt` | 同上 |
| `ui/AppRoot.kt` | `meal` / `event` 路由不再传 `onOpenSettings` |

**不动**：数据层（Room / DAO / PhotoStore）、同步层（SyncEngine / SyncManager / WebDavClient）、通知、设置页内部结构。

## 五、风险与取舍

1. **设置入口收敛**：饮食页 / 事件页无法直达设置，必须切回穿搭。这是「统一顶部栏」的代价，需产品确认。
2. **胶囊宽度动画**：`weight` 不支持动画，必须改成「固定宽胶囊 + Spacer(weight 1f)」结构，否则动画不生效或引起整行重排。
3. **单图不再贴边**：会牺牲一点照片的沉浸感（画面变小 24dp 宽），但换来三处留白统一。若更看重沉浸感，可只在"有备注文字"时才加内边距，让无备注单图继续贴边——需要二选一。
4. **备注折叠**：收起状态点一下才出现输入框，比原来永远可见多一次点击。可用性上略降，但换掉 101dp 空白是值得的。
